# 12주차 Python 파서 PyPI 버전 목록 캐시

검증일: 2026-11-10 (Asia/Seoul). 이 문서는 최초 캐시 도입 단계의 검증 기록이다.
후속 정확도 개선과 선언 후처리 성능 분석은 별도 문서를 참고한다.

## 구현

python-parser/python_parser.py의 _resolve_version()은 정확한 고정 버전을 먼저 반환하고,
범위가 있으면 후보 목록에서 조건을 만족하는 최신 정식 버전을 선택한다.
공유 전이 의존성은 그래프 확장 중복 방지 전에 버전 해석을 거치므로 같은 목록 조회가 반복됐다.

get_available_versions()의 정상 반환값을 canonicalize_name(requirement.name) 키로 캐싱한다.
대소문자 및 -, _, . 표기를 정규화하며 버전 조건별 필터링은 각각 수행한다.
예외가 발생하면 캐시에 저장하지 않아 같은 분석에서 재시도할 수 있다.
정상적인 빈 목록은 재사용하고, 조건 불충족을 패키지 전체의 실패로 저장하지 않는다.
parse() 시작 시 초기화하여 다른 분석 실행에서 오래된 목록을 재사용하지 않는다.

extras, marker, 확정·추정·미확정 정책, 재귀 및 get_dependencies() 중복 방지는 유지했다.

## 호출 횟수 검증

benchmark_api_calls.py는 부모 두 개가 같은 shared>=1.0을 요구하는 Mock PyPI 사례다.
원본 HEAD와 캐시 도입본을 임시 사본에서 실행하여 기존 결과를 덮어쓰지 않았다.

| 지표 | 도입 전 | 도입 후 |
|---|---:|---:|
| shared 버전 목록 조회 | 2 | 1 |
| 메타데이터 조회 합계 | 3 | 3 |
| shared 메타데이터 조회 | 1 | 1 |
| 결과 노드 수 | 3 | 3 |

버전 목록 호출 50% 감소이며 실제 HTTP 응답 시간의 50% 감소를 뜻하지 않는다.
Mock CPU 시간과 API 대기 절감은 [성능 분석](week12-performance-analysis.md)에서 구분한다.

## 회귀 검증

기존 파서 테스트 59개에 신규 캐시 회귀 9개를 추가해 68 PASS였다.
도입 당시 전체 오프라인 CI는 438 PASS였다. 이 수치는 이후 단계의 총 테스트 수와 구분한다.

신규 사례는 공유 전이 조회 1회, requirements/TOML의 독립 범위 선택 2개,
이름 정규화, 실패 후 재시도, 같은/다른 입력의 다음 분석에서 재조회 2개,
정상 빈 목록 재사용, 불충족 조건 이후 다른 조건의 정상 선택이다.

범위별 선택 버전·부모 연결·메타데이터 호출 수도 확인했다.
회귀 코드는 python-parser/test/test_version_list_cache.py에 있다.
